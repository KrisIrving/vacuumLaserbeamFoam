# Fixed-state optical diagnostic implementation

After the weighted partition failed cost and physics gates, add a diagnostic to separate the laser calculation from evolving CFD. A default-off capture/trace branch executes before flux correction/time advancement. Capture writes the original partition's filtered alpha, normal and resistivity. Trace reads those shared inputs, updates the unchanged laser algorithm once, explicitly reports its rank/global profile, writes deposition/rayQ and reports zero changes in T/alpha/epsilon/U.

RunFrozenLaser rebuilds both affected targets, checks the loaded binary/library, prepares copied 48-rank checkpoints, captures and reconstructs optical inputs, repartitions the candidate with the same checkpoint rayQ weights and verifies exact initial/input internal fields. Both trace jobs stay at 180 us. Final optical fields are reconstructed onto the same global mesh and checked separately from total absorbed power. Binary provenance includes capture. Five-minute solver budgets and native utility timeouts; existing shutdown grace and build/copy time are additional. Archive includes distinct capture/variant logs and all new gates.

Normal calls retain their original three-argument API and update/reporting path. A diagnostic overload suppresses automatic reporting only for the frozen call. No acceleration, absorption, stepping, transport or material-model change is claimed. All 69 local regression tests pass, including unchanged legacy collectors, shared-input acceptance, state evolution rejection, unequal-input rejection, spatial failure despite equal power and capture time-advancement rejection. Bash syntax passes. Actual OpenFOAM compilation and native execution remain Ubuntu validation. See tests/m247Performance/FROZEN_LASER.md.
