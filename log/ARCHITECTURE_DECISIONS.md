# Architecture decisions

## ADR-001 — Preserve upstream solver

**Status:** accepted

The original `laserbeamFoam` remains untouched as a regression reference.
`vacuumLaserbeamFoam` is developed as a parallel solver.

Reason: physical-model development will be easier to verify if the upstream
implementation remains runnable in the same repository.

## ADR-002 — First bootstrap is physics-equivalent

**Status:** accepted

Phase 1 introduces no intentional physics change. The initial
`vacuumLaserbeamFoam` equations are copied from LaserbeamFoam V3.0.

Reason: solver renaming/build integration must be verified separately from new
vacuum physics.

## ADR-003 — Separate three pressure concepts

**Status:** accepted

Maintain distinct concepts:
- `pRef`: reference pressure used by thermodynamic/saturation correlations;
- `pChamber`: experimental chamber absolute pressure (target 0.6 Pa);
- `pCFD`: pressure field used by pressure-velocity coupling.

Do not represent the experimental chamber pressure merely by setting `p_rgh`
or by replacing V3.0 `p0` with 0.6 Pa.

## ADR-004 — Outer VOF phase is initially a numerical void phase

**Status:** accepted for first production model

At 0.6 Pa the outer VOF phase should not be interpreted as a faithful continuum
argon flow. It remains as a numerical phase required for free-surface tracking
and pressure-velocity coupling.

Its numerical properties must later pass sensitivity tests.

## ADR-005 — Unified evaporation/recoil model

**Status:** accepted / implementation started

Evaporation mass flux, evaporation heat loss, and recoil pressure must be
generated by one model interface rather than unrelated equations in
`TEqn.H` and `UEqn.H`.

## ADR-006 — Do not start with explicit evaporation volume removal

**Status:** accepted for early phases

Initially use evaporation mass flux for heat loss and recoil closure while
keeping direct VOF mass removal disabled. Add interface recession only after
the thermal/momentum model is independently validated.

## ADR-007 — compressibleLaserbeamFoam is a reference branch, not the initial base

**Status:** accepted

Its explicit liquid-vapour transfer implementation is useful for later design,
but the first 0.6 Pa solver will not treat the whole chamber as an ordinary
compressible continuum gas.

## ADR-008 — Radiation remains active in vacuum

**Status:** accepted

Conventional environmental gas convection is expected to be negligible at the
target pressure, but thermal radiation to chamber surroundings is retained and
will be implemented explicitly.

## ADR-009 — Backward-compatible model selection

**Status:** accepted

During Phase 2, `transportProperties` may specify
`evaporationModel legacyAnisimov;`. If the entry is absent, the solver defaults
to `legacyAnisimov` so unmodified V3.0 cases remain runnable. A dedicated
`vacuumProperties` dictionary is deferred until pressure-aware models are added.
